## 10. Remaining limitations

1. Rollback step 1 (literal previous-artifact redeploy) is technically validated, not tested (§8) — no prior artifact exists.
2. Multi-instance/serverless rollback and scaling behaviour untested (no such environment locally).
3. `application version 0.1.0-rc.1` is a release candidate stamp; a versioning/release-tagging process (e.g. CI-generated manifests on tag) is future process work.
4. Browser smoke covers the five mandated safety-critical badge paths only — deliberately not a broad UI programme.
5. E2E/smoke run hermetically (`LLM_PROVIDER=macro`); hosted-provider behaviour in staging E2E is exercised by unit-mocked suites, not live provider calls.
6. The disposable Neon databases created for verification (`dentai_phase12_rc`, `dentai_phase12_mig`, `dentai_phase12_e2e`) can be dropped post-cutover; they contain only synthetic data.
