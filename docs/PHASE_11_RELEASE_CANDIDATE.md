## 5. UI verification ("Verified from Audio" fail-closed display)

All four badge paths require an engine-computed verdict, never note existence:

- `ChairsideWorkspace` — badge only when `grounding?.isFullyGrounded === true` (explicit `true`); macro path shows "Template Applied", never a verified claim.
- `ClinicalNoteEditorPanel` — renders whatever badge was passed; comment documents the Phase 5 fail-closed rule.
- `DayScheduleQueue` — `item.isFullyGrounded === true` else "Clinician Verification Required".
- PMS canonical badge passthrough — `statusBadge` is computed inside `subsecondAlignment` (server-side, `isFullyGrounded` → verified), never client-asserted.

Empty/missing audit, unverified, rejected, corrected, offline-draft and provider-failure states all resolve to a non-verified badge or no badge.

## 6. Defects found *by* staging verification (fixed in this phase, gates re-run)

| # | Defect | Severity | Fix |
| --- | --- | --- | --- |
| S-1 | Consultation POST/PUT merged client bodies without protection — a client could self-supply `groundingAudit.isApprovedForSigning` (or carry a stale approval across an edit) and then sign | Critical (authz of signing) | Governance middleware now strips server-derived fields (`groundingAudit`, `groundingReport`, `sovereignty`, `facts`, `recordVersion`, `revisions`, `identityNeedsReview`) from every consultation write |
| S-2 | No recompute of the approval after a clinician edit — a generation-time approval would outlive content changes | Critical | Server recomputes `verifyNoteGrounding` over the merged record on every POST/PUT (both Postgres and JSON paths) |
| S-3 | Worker-persisted durable records lacked the `groundingAudit` stamp and canonical `consent` object — the sign gate would have refused every legitimate durable note forever; sign gate also accepted only one consent shape | Critical (flow-blocking) | Worker stamps `output.groundingAudit` + canonical `consent` (from captured consent fields); gate accepts canonical `consent.obtainedAt` or legacy `consentObtained`+`consentCapturedAt` pair |
| S-4 | Worker hard-coded `noteOrigin.engine: 'gemini'` regardless of actual provider | Minor (provenance honesty) | Worker now stamps the actual provider |

Regressions added: the staging harness asserts the self-approval strip (`audit field remains server-owned after a client write attempt`), born-unapproved worker notes, fail-closed signing of incomplete notes, server-recomputed approval, server-minted seal and replay refusal.
