## 1. Executive Summary & Purpose

Phase 4 establishes the **Deterministic Clinical Evaluation Harness** for DentAI.

### The Central Question
> **Given a known dental clinical utterance or transcript, did DentAI extract the correct ClinicalFacts?**

This evaluation harness measures extraction accuracy independently from:
- UI presentation or formatting
- LLM prose eloquence
- Subjective reviewer impressions
- Model confidence scores
- Whether the generated clinical note "looks reasonable"

## 2. Gold-Standard Evaluation Schema & Dataset Versioning

The gold standard dataset is a version-controlled clinical asset (`v1.0.0`) defined in [src/lib/clinicalEvaluation/corpus.ts](file:///c:/Users/swati/Downloads/dentai/src/lib/clinicalEvaluation/corpus.ts).

### Case Specification (`ClinicalEvaluationCase`)
```typescript
export interface ClinicalEvaluationCase {
  readonly id: string;
  readonly datasetVersion: string;
  readonly description: string;
  readonly category: ClinicalEvaluationCategory;
  readonly difficulty: 'basic' | 'intermediate' | 'complex' | 'adversarial';
  readonly isAdversarial: boolean;
  readonly clinicalDomain: string;
  readonly transcript: EvaluationTranscript;
  readonly expectedFacts: ReadonlyArray<ExpectedClinicalFact>;
  readonly expectedWarnings?: ReadonlyArray<string>;
  readonly tags?: ReadonlyArray<string>;
  readonly rationale?: string;
}
```

### Invariants:
1. **Deterministic Authorship:** Expected facts are manually authored, reviewed, and static. They are **never** inferred or generated by an LLM at runtime.
2. **Version Control:** All cases carry a strict `datasetVersion` (current: `v1.0.0`).
3. **Adversarial Mandate:** At least **30%** of cases are deliberately designed adversarial traps targeting common semantic failure modes.

## 3. Curated Benchmark Corpus & Adversarial Coverage

The `CLINICAL_EVALUATION_CORPUS_V1` dataset spans 10 critical clinical categories:

| Category | Description | Primary Failure Mode Tested |
|---|---|---|
| **Speaker** | Patient vs Clinician attribution | Patient complaint recorded as clinician observation |
| **Negation** | Direct negation vs diagnostic uncertainty | "No caries" vs "I don't think there is caries" |
| **Temporal** | Planned, completed today, historical | Planned procedure coded as completed today |
| **Anatomy** | ISO 3950 tooth numbers, surfaces, arches | Wrong tooth (36 vs 46), illegal anterior occlusal surface |
| **Dental Findings** | Caries, fractures, defective restorations | Existing restoration described without procedure performed |
| **Procedures** | Restorative, surgical, endodontic | Discussion recorded as performed procedure |
| **Anaesthesia** | Drug, volume, adrenaline, technique | Missing vasoconstrictor or wrong administration route |
| **Medication** | Anticoagulants, antiplatelets, antiresorptives | Negated drug history recorded as active prescription |
| **Consent** | Risks, alternatives, patient deliberation | Undecided patient treated as consented |
| **Clinical Ambiguity** | Hedging, differential diagnoses | Guess converted into definitive diagnosis |

## 4. Deterministic Comparison Engine & Semantic Matching

Rather than naive JSON equality or string diffing, the comparison engine ([src/lib/clinicalEvaluation/evaluator.ts](file:///c:/Users/swati/Downloads/dentai/src/lib/clinicalEvaluation/evaluator.ts)) uses **bipartite semantic matching**:

1. **Affinity Matrix:** Calculates semantic affinity based on `type`, anatomical target (`teeth`), and clinical condition/procedure identity.
2. **Greedy Bipartite Pairing:** Matches actual facts to expected facts independently of ID generation or property ordering.
3. **Unpaired Extraction Detection:**
   - Unmatched expected facts are flagged as **`missed_fact`** (False Negatives).
   - Unmatched actual facts are flagged as **`hallucinated_fact`** (False Positives).

## 5. 16-Point Clinical Error Taxonomy

Failures are categorized into 16 distinct domain error types:

```typescript
export type ClinicalErrorType =
  | 'missed_fact'                 // Expected clinical assertion was omitted
  | 'hallucinated_fact'           // Fabricated clinical assertion
  | 'wrong_fact_type'             // Cross-domain mismatch (e.g. procedure vs symptom)
  | 'wrong_speaker'               // Inverted speaker (e.g. patient vs clinician)
  | 'wrong_evidence_type'         // Epistemic inversion (e.g. patient_reported vs clinician_observed)
  | 'wrong_anatomy'               // Wrong tooth or contradictory FDI reference
  | 'wrong_surface'               // Wrong or illegal dental surface
  | 'wrong_status'                // Status mismatch (e.g. planned vs performed)
  | 'wrong_temporal_context'      // Temporal mismatch (e.g. next_appointment vs completed_today)
  | 'wrong_certainty'             // Epistemic certainty mismatch (certain vs uncertain)
  | 'wrong_value'                 // Clinical payload divergence
  | 'wrong_negation'              // Inverted negation (positive vs negated)
  | 'unsupported_detail'          // Missing required clinical detail
  | 'evidence_mismatch'           // Fact grounded in contradictory utterance
  | 'provenance_error'            // Fabricated or inverted timestamps
  | 'structural_validation_error';// Inadmissible domain invariant
```

## 6. 4-Tier Clinical Error Severity Classification

Every error is assigned a deterministic severity grade:

| Severity | Definition & Clinical Impact | High-Risk Examples |
|---|---|---|
| **Critical** | Immediate risk to patient safety, fraudulent billing, or inverted clinical reality | • `performed ↔ planned`<br>• `negated ↔ positive finding`<br>• Wrong tooth (e.g. #36 vs #46)<br>• Patient complaint coded as clinician observation<br>• Fabricated invasive procedure or allergy<br>• Fabricated evidence timestamps |
| **High** | Material diagnostic or treatment planning divergence | • Wrong status (e.g. observed vs discussed)<br>• Wrong temporal window (historical vs current)<br>• Hallucinated non-invasive finding<br>• Wrong medication dose or frequency |
| **Moderate** | Secondary clinical discrepancy | • Missing optional clinical detail<br>• Surface divergence on a multi-surface prep<br>• Epistemic certainty mismatch (certain vs uncertain) |
| **Low** | Minor documentation or provenance variance | • Text normalization differences<br>• Minor evidence boundary divergence |

## 7. Deterministic Metrics & Safety Indicators

### Primary Extraction Metrics
- **Fact Precision:** $\frac{\text{True Positives}}{\text{Total Actual Facts}}$
- **Fact Recall:** $\frac{\text{True Positives}}{\text{Total Expected Facts}}$
- **Fact F1:** $\frac{2 \cdot P \cdot R}{P + R}$

### Dimension Accuracies
Calculated independently for each matched fact pair:
- `speakerAccuracy`
- `evidenceTypeAccuracy`
- `statusAccuracy`
- `temporalAccuracy`
- `anatomyAccuracy`
- `certaintyAccuracy`
- `typeAccuracy`
- `valueAccuracy`

### Clinical Safety Failure Counters
- **Negation Failures:** Instances where negated findings were converted to positive assertions or vice-versa.
- **Temporal Inversions:** Instances where planned future work was marked as performed today.
- **Anatomical Failures:** Errors in tooth numbering, quadrants, or surfaces.
- **Provenance Violations:** Fabricated, extrapolated, or inverted timestamps.
- **Hallucinations:** Unsupported assertions generated by the model.

---

## 8. Anti-Patterns & Hard Safety Guarantees

1. **NO LLM-as-a-Judge:** An LLM is **never** used to evaluate or grade clinical extraction results. Evaluation is 100% deterministic and reproducible.
2. **NO Synthetic Timestamps:** The evaluation harness strictly forbids the manufacture or extrapolation of timestamps. If the input transcript lacks millisecond offsets, absence of timestamps is the expected state.
3. **Model & Provider Agnostic:** The evaluation engine operates strictly on `ClinicalFact` domain assertions. It can evaluate extractions from Gemini, Groq, local offline models, or deterministic rule engines with equal fidelity.
