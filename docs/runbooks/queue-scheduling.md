# Making note completion durable (queue scheduling)

## The problem this fixes

Notes are generated by a queue: a clinician submits a consultation, the server
claims the job, calls the AI, and the browser polls for the result. Claiming is
atomic (`FOR UPDATE SKIP LOCKED`), so two workers can never double-charge a
clinic.

But a queue only advances when something ticks it. Previously the only ticks
were (a) a clinician submitting another note, and (b) the browser polling. On a
serverless host that means:

- a note submitted on a laptop that is then closed can sit `queued` for as long
  as nobody else uses the product;
- stuck-job requeue and expiry sweeps never run, because they run inside a tick;
- a 45s→6min backoff can outlive the browser's 90s patience, leaving the
  clinician looking at a spinner for a note that is quietly waiting.

A background scheduler fixes all three. It is the difference between "we have a
durable queue" and "we have a durable queue as long as someone is looking".

## How it is wired

| Piece | Location |
|---|---|
| Route | `GET|POST /api/cron/drain` in `src/server/opsRoutes.ts` |
| Auth | `CRON_SECRET`, compared in constant time |
| Work | `drainQueue()` in `server.ts` → one full tick + open-job count |
| Long-running hosts | `DENTAI_QUEUE_INTERVAL_MS` starts an in-process timer |

`/api/ops/drain` (POST) does the same work authenticated with
`DENTAI_OPS_SECRET`, for you to trigger by hand while debugging.

## Option 1 — Vercel Cron (if you deploy on Vercel)

`vercel.json` already contains:

```json
"crons": [{ "path": "/api/cron/drain", "schedule": "*/1 * * * *" }]
```

Setup:
1. Set `CRON_SECRET` in the project's environment variables (Production **and**
   Preview if you test against preview).
2. Vercel sends `Authorization: Bearer $CRON_SECRET` on each invocation; the
   route accepts that, `x-cron-secret`, or a bare secret.
3. Confirm it is working:
   `curl -s https://<app>/api/health` → `{"status":"ok", ...}`, then
   `curl -s -H "Authorization: Bearer $CRON_SECRET" https://<app>/api/cron/drain`
   → `{"ok":true,"openNoteJobs":N}`.

**Plan gotcha:** Vercel's Hobby plan only permits daily cron invocations, so a
`*/1` schedule will not run every minute there. Either upgrade to Pro or use
Option 2 — a queue that drains once a day is not durable enough to sell.

## Option 2 — Any external pinger (plan-independent)

Works on any host, including Freebuff-managed hosting and a plain VM.

1. Set `CRON_SECRET` to a long random value.
2. Create a job that every 60 seconds issues:

```bash
curl -fsS -X POST https://<app>/api/cron/drain -H "x-cron-secret: $CRON_SECRET"
```

3. Options: cron-job.org, UptimeRobot (monitor + keyword), a GitHub Actions
   scheduled workflow, or a 1-minute timer on a VPS. GitHub Actions cron is
   free but can be delayed several minutes under load — adequate, not ideal.
4. Point the same tool at `/api/health` and alert if it is not `200`, or if
   `"database":"unavailable"` appears.

## Option 3 — Long-running host (VM or container)

`node server.js` with:

```bash
DENTAI_QUEUE_INTERVAL_MS=60000
```

The process drains itself every minute and needs no external pinger. The timer is
`unref()`'d so it never holds the process open, and it is disabled in tests.

## Verifying it actually works

1. Sign in, start a consultation, submit a note, then **close the tab
   immediately**.
2. Wait two minutes.
3. Reopen the app: the note should be complete (or failed with a reason), not
   still queued.
4. If it is still queued, check in this order: is `CRON_SECRET` set? does the
   scheduler's response say `ok:true`? are there errors in `/api/ops/telemetry`
   (`openNoteJobs` climbing means jobs are arriving but not completing)?

## Alerting you should add (solo-founder affordable)

- `openNoteJobs` above ~20 for more than 10 minutes → something is wrong with the
  AI path (quota, key, or region).
- `/api/health` not `200`, or `database` not `ok` → database or credentials.
- Any `5xx` rate above ~1% for 15 minutes → set `ERROR_WEBHOOK_URL` and let the
  server push alerts to your phone.
