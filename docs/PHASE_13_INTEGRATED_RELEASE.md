## 5. Clinical safety invariants (release blockers) — verified on the release tree

- **Client cannot self-approve:** governance strips client-supplied `groundingAudit`/`facts`/`recordVersion`/`revisions`/`identityNeedsReview`; API E2E asserts "audit field remains server-owned after a client write attempt". **HELD.**
- **Clinical edits invalidate prior approval:** browser E2E Case D and the production smoke (§8) confirm a server-recomputed audit drops approval after a correction. **HELD.**
- **Verification display is fail-closed:** `deriveGroundingBadge` requires `groundingAudit.isApprovedForSigning === true`; unverified records never display "Verified from Audio" (smoke Case A). **HELD.**
- **Macro never verified:** `Template Applied` short-circuit (smoke Case C; UI safety T10). **HELD.**
- **Sign-off is server-authoritative:** `signOffClient.ts` only transports; the server revalidates everything and mints the seal. **HELD.**
- **Sign-off fails closed:** 422 `GROUNDING_NOT_APPROVED` / `VERIFICATION_BLOCKING_STATE` / `CONSENT_MISSING` / `EMPTY_NOTE` covered by `tests/signOffValidation.test.ts` (12 tests) and exercised in smoke + E2E. **HELD.**
- **Optimistic concurrency:** 409 `STALE_WRITE` with server copy; visible conflict banner. **HELD.**
- **Replay protection:** reused nonce → 409 `REPLAY`/`STALE_VERSION` (API E2E + `signOffValidation` suite). **HELD.**
- **Evidence integrity:** gold set "Evidence grounding 100.0%, Provenance errors 0.0%"; anti-fabricated-timestamp validation asserted in the E2E. **HELD.**
- **Audit PHI-free:** API E2E asserts no transcript content in the audit trail and PHI-free ops telemetry. **HELD.**

## 6. Hosted-provider facts seam (Phase 13 §9)

The canonical ClinicalFact pipeline does **not** yet feed the hosted note path — `CLINICALFACT_INTEGRATION_AUDIT.md` documents this exactly: the production path (`runHostedGeneration` → `finalizeHostedNoteOutput`) emits a prose note + `groundingAudit`/`groundingReport`, and canonical facts are exercised by the macro/deterministic path, the durable-worker fact checks and the API E2E. Consequences verified on the release tree: the facts/evidence strip renders only for fact-bearing records and is empty (never fabricated) otherwise; **all canonical safety gates (grounding recompute, fail-closed sign-off, seal, replay, concurrency) are provider-independent and hold on every path**. This is the documented, non-blocking Phase 12 limitation; it does not bypass any safety invariant. Inventing facts client-side to fill the strip would violate evidence integrity (§4.9 of the release plan) and was not done.

## 7. Postgres release gate — closed via CI on the release SHA
